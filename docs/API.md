# Python API and generated browser client

FastAPI is the only active REST API implementation. Interactive local docs: `http://127.0.0.1:8000/docs`; runtime schema: `/openapi.json`; committed schema: `backend/openapi.json`. Responses use camelCase contracts to preserve the current browser interface. `age_band` is the query parameter name. Inputs forbid unexpected fields; bodies are bounded to 16 KiB and error messages never echo submitted inputs.

| Endpoint | Access and result |
|---|---|
| `GET /health/live` | Process liveness; synthetic-only mode |
| `GET /health/ready` | PostgreSQL migration revision and Redis checks; 503 until ready |
| `GET /api/v1/missions?age_band=10-12` | Public reviewed versions, `{items: [...]}` |
| `GET /api/v1/missions/{version_id}` | One immutable published version |
| `GET /api/v1/auth/session` | Development/test opaque bearer session; production synthetic path closed |
| `POST /api/v1/auth/register` | Always 503: real enrollment closed |
| `POST /api/v1/ai/respond` | Always 503: generative learner AI closed |
| `POST /api/v1/attempts` | Authorized synthetic learner; published age-compatible version |
| `GET /api/v1/attempts/{attempt_id}` | Scoped authorized attempt |
| `POST /api/v1/evidence` | Authorized active attempt; bounded typed payload |
| `GET /api/v1/learners/{learner_id}/evidence` | Scoped evidence, expired records omitted |
| `DELETE /api/v1/evidence/{evidence_id}` | Authorized adult only |
| `POST /api/v1/attempts/{attempt_id}/complete` | Seven-step evidence, distinct ideas and two fair-test measurements |

## Regenerate

From the repository root:

```sh
cd backend
uv run --frozen python -m educationos.export_openapi
uv run --frozen python -m educationos.export_openapi --check
cd ..
npm run api:generate
npm run api:check
```

`src/lib/api/schema.d.ts` is generated by the pinned `openapi-typescript`; `openapi-fetch` supplies the typed browser transport. Do not hand-edit generated declarations. CI checks both schema and generated type drift. Browser `PublishedMission` runtime validation supports the current UI; server Pydantic remains authoritative for writes.

Next forwards `/api/v1/*` using server-only `PYTHON_API_URL`, selected at dev startup or production build. The demo only reads curriculum; local notes/export/reset do not call protected writes. Its fallback is explicitly labeled, and a changed mission version cannot silently replace an in-progress demo draft.

## Synthetic authenticated examples

Run the optional Compose seed from README locally to obtain a one-hour token and synthetic learner ID. Use the returned token only in a private HTTP client's Authorization Bearer field. Never create a token in frontend code, commit it, log it, or invent consent on an HTTP endpoint.

Example JSON for `POST /api/v1/attempts` (substitute IDs returned by seed/catalog):

```json
{"learnerId":"e0600000-0000-4000-8000-000000000002","missionVersionId":"00000000-0000-4000-8000-000000000000"}
```

The all-zero mission version above is an explicit placeholder, not a published mission. Use the real `id` returned by the curriculum endpoint for age band `10-12`.

Example evidence body, with the actual attempt ID from the start response:

```json
{"attemptId":"00000000-0000-4000-8000-000000000000","step":"experiment","payload":{"kind":"measurement","label":"baseline","value":12,"unit":"seconds"}}
```

Completion needs each of the seven documented steps, two distinct imagine ideas, baseline/redesign measurements in seconds within 0–60, plus written hypothesis/reflection/transfer. These rules establish a recorded synthetic journey, not scientific mastery or experiment safety approval. No external model receives evidence.

The API uses bearer authentication with no browser ambient session cookie; CORS is not an authorization mechanism. Unknown, expired, revoked and forged identities cannot establish access. Production synthetic private endpoints stay closed regardless of token.
