# Anatomy lessons for EducationOS

Use Anatomy to author models that children can inspect, change and explain. Begin with exact count and geometry lessons, then introduce physical models only when their assumptions and evidence are clear.

- [Deep audit](AUDIT.md): capabilities, source findings, integration work, accessibility, performance, scientific limits and licensing.
- [Class plan](CLASS_PLAN.md): high-interest lessons across the five portal subjects, age adaptation, learning checks and private artifacts.
- [Professional prompt pack](PROMPTS.md): reusable 2D and 3D authoring contracts, complete pilot briefs, a separate mesh-asset workflow, and review/repair instructions.
- [Audit evidence](audit-evidence.json): reviewed revision, executed checks, sizes and verification limits.

Anatomy revision: `e9488296a44211c42701ff71705b7901470ec78f`. The audit supports selected lesson integration. It does not replace the portal's curriculum, accounts, storage or code runner. The three pilot classes are now implemented in the learner portal: Loop Loom, Same Half Different Shape, and Hidden Cube Builder. See [implementation notes](IMPLEMENTATION.md) for routes, learning checks, fallbacks, source attribution, and verification scope. The broader class plan remains an authoring roadmap.

Compelling lessons begin with a question a child can investigate: “Can three lines make twelve tiles?” or “Are cubes still there when you cannot see them?” A strong result is an explanation and a fresh successful application. Voluntary return and private export can be secondary signals; virality is not guaranteed.
